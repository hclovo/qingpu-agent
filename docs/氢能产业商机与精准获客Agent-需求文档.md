# 氢能产业商机与精准获客 Agent 需求文档

> 版本：V1.0  
> 日期：2026-08-17  
> 状态：MVP 开发基线  
> 适用企业：北京氢璞创能科技有限公司

## 1. 项目概述

### 1.1 背景

氢璞创能聚焦燃料电池电堆、燃料电池系统和 PEM 制氢装备的研发、制造与销售，产品覆盖重卡、物流车、船舶、矿卡、轨道交通、储能、无人机和两轮车等场景。企业当前的直接痛点是市场推广人员不足，难以持续跟踪分散的产业动态、识别潜在客户并形成可执行的跟进建议。

本项目建设一套“行业信号发现—潜客识别—商机评分—产品匹配—Agent 研判—人工跟进”的工作台，帮助少量市场人员优先处理高价值商机。

### 1.2 产品定位

本产品首先是一个“企业关系与商机自动化 Agent”，其次才是商机看板。Agent 围绕企业与客户、潜客、上游厂商和生态伙伴的长期联系开展工作：理解企业资料与往来记录、回答业务问题、发现关系维护节点、准备沟通内容、识别上下游协同和销售机会，并推动人工确认后的跟进闭环。

Web 不是独立的传统 CRM，而是 Agent 的可视化工作台和数据入口：让用户方便地与 Agent 对话、补充文件/网页/业务记录到知识库、查看关系上下文和商机、确认 Agent 建议。系统不自动代表企业联系外部对象；关键外发、报价和技术承诺必须由人确认。

### 1.3 项目目标

- 建立可持续补充的企业知识库和上下游关系上下文。
- 主动发现久未联系、待回复、合作窗口和信息缺口，帮助企业维持关系温度。
- 通过自然语言 Agent 统一查询关系、知识、产品和商机，并生成每日行动简报。
- 将分散的行业线索与往来信息转化为结构化潜客和商机。
- 对商机进行可解释、可复核的优先级排序。
- 基于场景、功率、认证和客户类型匹配氢璞产品。
- 为销售输出证据链、切入点、风险和下一步行动。
- 在未配置大模型密钥时仍能完整演示核心闭环。

### 1.4 成功指标

MVP 验收以功能闭环为主，试运行后再建立业务基线：

| 指标 | MVP 目标 |
| --- | --- |
| 高潜商机处理效率 | 用户可在 3 分钟内从看板进入商机详情并完成一次研判 |
| Agent 可操作性 | 用户可通过自然语言查询关系/知识/商机，并得到带来源或明确待核实项的答复 |
| 关系维护 | 每日简报能识别到期跟进、沉默关系和高优先级协同机会 |
| 知识补充 | 用户可在 Web 中添加文本、URL 和结构化文件内容，并立即用于检索/Agent 上下文 |
| 可解释性 | 每条评分都展示维度得分、匹配产品、证据与风险 |
| 结构化输出合规率 | Agent 输出通过 Zod Schema 校验；失败时自动回退规则结果 |
| 可用性 | 无模型密钥时看板、筛选、评分、匹配、状态更新均可用 |
| 自动化测试 | 评分、匹配和核心 API 具有自动化测试，构建通过 |

## 2. 资料分析结论

### 2.1 输入资料

原始资料位于 `T04_氢能产业商机与精准获客Agent/企业资料包01_氢璞创能/`，包括：

1. 企业资料说明：明确命题、企业痛点、资料授权及补充规则。
2. 2025 企业宣传册：公司能力、解决方案、应用场景、案例和合作伙伴。
3. 2025 产品单页：27 个型号，覆盖碳复合板电堆、金属电堆、空冷电堆、车用/船用系统及 PEM 制氢系统。
4. 商机判断文档：行业说明、术语卡、业务流程、脱敏样例、产品匹配矩阵和 5 个案例。

资料敏感性为 A 级，可用于开发和演示；允许使用公开资料及合理模拟数据。原始文件保持只读，系统种子数据需保留来源名称、页码/章节、资料时间和“公开/脱敏/模拟”标签。

### 2.2 关键业务事实

- 目标客户包括系统集成商、商用车整车厂、船舶制造/航运企业、轨交装备企业、大型用能企业、地方政府和产业园区。
- 典型需求包括燃油重卡替换、矿区/港口绿色运输、船舶动力清洁化、轨道交通动力、分布式发电、氢储能及 PEM 制氢。
- 可用产品基线包括 ST 系列电堆、E200 车用系统、OCEAN100/200 船用系统、CESP250/500/1000 集装式 PEM 制氢系统。
- 现有数据只有少量成功案例，缺少负样本、商机输赢、联系人和实时数据，不能把模型分数解释为成交概率。

### 2.3 数据质量约束

- 宣传册部分数字存在字体编码乱码，产品册多数文字已轮廓化，自动入库前必须人工校验关键参数。
- 资料主要为 2025 年版本，系统必须显示来源时间，不得把旧信息表述为实时事实。
- “500kW 级”“兆瓦级”“高铁 380kW”等营销/样例名称与产品型号存在别名或版本差异，匹配结果需要标记待产品专家确认。
- 模拟企业和模拟信号必须显著标识，不能与已核验公开事实混淆。

## 3. 用户与使用场景

### 3.1 用户角色

| 角色 | 主要诉求 | MVP 权限 |
| --- | --- | --- |
| 市场/销售 | 发现高潜线索、维护客户关系、准备跟进沟通 | Agent 对话、浏览、研判、记录联系、更新状态 |
| 采购/供应链 | 维护上游厂商、识别供应协同和风险 | Agent 对话、关系记录、知识补充 |
| 销售负责人 | 查看关系健康度和商机结构、校准优先级 | 同上；MVP 暂不含团队分配 |
| 产品/售前 | 审核产品适配、补充技术边界和知识 | 查看匹配证据、维护知识条目 |
| 系统管理员 | 管理数据源、模型和评分版本 | MVP 通过环境变量和种子配置管理 |

### 3.2 核心使用场景

1. 用户进入 Agent 工作台，查看“今天该联系谁、为什么联系、应准备什么”的行动简报。
2. 用户用自然语言询问客户、供应商、产品、历史资料或近期商机，Agent 调用业务工具回答。
3. 用户通过文本、URL 或本地文本类文件补充知识，并为条目标注关系对象、标签和来源。
4. 用户查看客户/潜客/上游厂商/伙伴关系，补充一次联系记录和下一步行动；Agent 据此更新关系提醒。
5. 用户打开商机看板，按行业、地区、等级或阶段筛选潜客，并查看证据和产品匹配。
6. 用户粘贴项目/采购/政策/新闻信号，让系统结构化并评分。
7. 用户点击“Agent 自动发现”，由 Mastra Agent 使用模型提供方的联网搜索寻找候选信号；无密钥时返回明确标注的演示结果。
8. 用户确认 Agent 生成的沟通提纲或建议后，再通过企业既有渠道人工触达。

## 4. MVP 范围

### 4.1 功能范围

#### F01 Agent 工作台与对话

- 提供自然语言对话入口，支持查询企业知识、关系、产品和商机。
- Agent 通过工具读取真实业务数据；回答需带知识来源、数据依据或明确“待核实”。
- 提供每日行动简报：到期跟进、久未联系关系、高潜商机、知识缺口。
- 根据选定关系或商机生成沟通准备，包括目标、建议问题、可用案例和风险；默认不外发。
- 无模型密钥时使用意图识别和检索规则回答常见查询，并明确当前为规则模式。

#### F02 关系中心

- 管理客户、潜客、上游厂商、合作伙伴四类关系对象。
- 展示关系健康度、最近联系、下次行动、关联商机、资料完整度和来源类型。
- 支持新增互动记录，包含时间、渠道、摘要、结果和下一步行动。
- 识别沉默关系、到期任务、供应协同和销售机会；模拟对象必须显著标识。

#### F03 知识库与数据补充

- 预置企业资料、产品、案例和术语的可追溯知识条目。
- Web 支持添加文本、URL 和 `.txt/.md/.csv/.json` 文件内容；记录来源、标签、关联关系和更新时间。
- MVP 提供关键词检索和 Agent Tool 查询；PDF/Word 新上传可登记元数据，深度解析/OCR 列入后续。
- 展示每条知识的处理状态：可用、待解析、需复核、失败。

#### F04 商机总览

- 展示商机总数、高潜数量、本周新增、平均分。
- 展示商机等级分布、行业分布和重点商机排行。
- 指标来源于当前数据集，不伪装为外部实时市场全量统计。

#### F05 商机雷达与筛选

- 以列表展示企业、商机标题、行业、地区、信号类型、评分、等级、阶段、更新时间。
- 支持关键词、行业、等级和阶段筛选。
- 支持进入详情及从当前页启动自动发现。

#### F06 商机详情与证据链

- 展示客户画像、需求场景、采购/项目信号及来源。
- 展示评分维度、加减分原因、证据置信度和资料时效。
- 展示推荐产品、匹配理由、约束缺口和待确认事项。
- 展示 Agent 摘要、切入策略、风险和建议动作。

#### F07 新信号研判

- 接收企业名称、标题、正文、行业、地区、来源、发生时间、预计规模和可触达程度。
- 校验必填项并调用确定性评分与产品匹配。
- 配置模型时调用 Mastra Agent 输出结构化研判；调用失败时返回规则结果并标明降级原因。
- 保存为新商机，避免同一请求重复提交造成重复记录（MVP 使用请求期间去重）。

#### F08 Agent 自动发现

- 用户输入目标行业/地区/场景关键词。
- 配置受支持模型时，Mastra Agent 使用 `webSearchTool` 搜索近期公开信息，并输出候选企业、信号、来源 URL、时间和证据摘要。
- 系统只把候选项作为“待核验”，再经过规则评分与人工审核；不得自动外发消息。
- 未配置模型时返回内置演示信号并明确 `mode=demo`。

#### F09 线索阶段管理

- 阶段：新线索、待核验、已研判、跟进中、已转化、已关闭。
- 支持更新阶段；关键阶段变更保留更新时间。
- MVP 不含多人分配、审批和完整审计日志。

#### F10 产品知识基线

- 展示产品名称、家族、核心参数、适用场景、认证和来源。
- 匹配时优先使用硬约束（场景、认证、功率区间），再计算软匹配。
- 所有技术参数用于线索预筛，不替代正式选型或报价。

### 4.2 商机评分规则 V1

总分 100 分，分数代表“当前跟进优先级”，不代表成交概率。

| 维度 | 权重 | 判断要点 |
| --- | ---: | --- |
| 场景/产品匹配 | 30 | 是否属于氢璞覆盖场景；功率/认证/产品家族是否匹配 |
| 需求与采购能力 | 20 | 明确数量、预算、客户规模、重复采购或示范项目能力 |
| 信号时效 | 20 | 30/90/180 天内信号分别获得不同分值 |
| 项目成熟度 | 15 | 从行业关注、规划、立项、招标、试运营到重复采购 |
| 可触达性 | 10 | 是否有公开商务渠道、既有伙伴关系或明确项目主体 |
| 战略价值 | 5 | 标杆客户、重点区域、可复制场景或产业链协同价值 |

等级：A（80-100，高潜）、B（65-79，重点培育）、C（50-64，持续观察）、D（0-49，低优先级）。每次计算保存 `scoreVersion=1.0.0` 和维度明细。

### 4.3 非 MVP 范围

- 自动发送邮件、短信、社交媒体消息或批量营销。
- 购买、爬取或推断非公开个人联系方式。
- 完整 CRM、报价、合同、回款和销售预测。
- 无人工确认的自动产品选型或技术承诺。
- 大规模爬虫、生产级 RAG、OCR 审核后台和多租户权限体系。

## 5. 数据需求

### 5.1 核心实体

| 实体 | 核心字段 |
| --- | --- |
| Product | id、型号、产品家族、额定/峰值功率、寿命、认证、适用场景、来源 |
| Relationship | id、名称、角色、行业、地区、健康度、最近联系、下一步行动、来源类型 |
| Touchpoint | 关系对象、时间、渠道、摘要、结果、下一步行动、记录人 |
| KnowledgeItem | id、标题、内容、类型、来源、标签、关联关系、处理状态、更新时间 |
| Lead/Opportunity | id、企业、行业、地区、标题、信号、阶段、评分、等级、来源、更新时间 |
| ScoreBreakdown | 评分版本、六个维度分数、理由 |
| ProductMatch | 产品、匹配分、匹配维度、缺口、理由 |
| SourceEvidence | 来源类型、标题、URL/文件、发布时间、抓取时间、证据摘录、置信度 |
| AgentInsight | 模式、摘要、机会类型、切入点、风险、建议动作、模型、生成时间 |

### 5.2 数据治理

- 来源类型必须区分 `public`、`enterprise-provided`、`demo-simulated`。
- 公开联系人只采集企业级商务渠道；如未来引入自然人信息，需增加合法性基础、来源、核验时间和删除机制。
- 外部内容需防提示注入：网页文本只能作为事实材料，不得改变 Agent 系统指令。
- 记录模型、Prompt/评分版本和降级状态，便于复核。

## 6. 非功能需求

- **技术**：全栈 TypeScript，前后端分离，使用 pnpm workspace；Node.js 22.13+。
- **性能**：本地种子数据下，普通列表 API P95 小于 300ms；Agent 请求单独显示运行状态和超时。
- **可靠性**：模型、搜索或网络异常不能影响规则评分和已存数据浏览。
- **安全**：模型密钥仅存后端环境变量；生产需补充认证、CORS 白名单、限流和日志脱敏。
- **可观测性**：API 返回 `requestId`；Agent 记录模式、模型、耗时和错误摘要，禁止记录密钥。
- **可访问性**：核心操作可使用键盘完成，状态不只依赖颜色表达。
- **兼容性**：支持当前主流桌面 Chromium 浏览器；首版优先 1280px 以上销售工作台。

## 7. 验收标准

1. `pnpm dev` 可同时启动前后端，Web 通过 `/api` 代理调用后端。
2. Agent 工作台能回答至少四类问题：知识查询、关系查询、商机查询和行动建议；无密钥时也有明确可用的规则回答。
3. 每日简报展示到期跟进、沉默关系和高潜商机，并可进入对应详情。
4. 用户能添加文本、URL 或文本类文件知识，保存来源和标签，并可立即检索。
5. 关系中心能区分客户/潜客/上游厂商/伙伴，记录一次互动和下一步行动。
6. 总览页正确展示种子商机统计、分布和高潜排行。
7. 商机页能按关键词、等级、行业和阶段筛选，详情页展示完整证据链。
8. 新信号提交后得到 0-100 评分、等级、评分拆解和至少一个产品匹配或明确“暂无匹配”。
9. 不配置密钥时系统以规则/演示模式正常工作；UI 明确提示当前模式。
10. 配置模型密钥时，Mastra Agent 返回通过 Schema 校验的摘要、风险和建议；失败后安全降级。
11. 自动发现结果包含来源 URL 和待核验标识，不会自动触达外部人员。
12. 核心 API、评分、匹配、关系和知识库测试通过，`pnpm check` 成功。

## 9. 风险与待确认项

- 真实销售效果需要 CRM 历史输赢数据校准；V1 权重只是可解释业务规则。
- 产品参数和别名需产品专家复核，尤其是兆瓦级、500kW 级和轨交产品。
- 公开网页搜索受模型提供方、站点条款和网络可用性影响。
- 生产落地前需确认数据保留期、用户权限、企业联系人使用规范及 CRM 对接方式。
